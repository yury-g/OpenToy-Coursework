# Background runtime observation and optional race

Owner wants to compare Blue, replacement Green, Orange StickS3 and Silver after charging above90%, unplugging those four USB cables, while Tab5 stays on USB. Faces stay available. Prepare and smoke-test now while charging; do not start a real discharge run. The second request is exploratory background battery understanding, not an automated destructive load/cycling test.

Tab5 alone changes firmware. Existing radio packets and charger configurations remain unchanged. A pure C++ observer accepts only fresh, valid, nonduplicate source samples from those four known boards. It keeps bounded overlaid SOC and voltage histories, recent five-minute slopes, continuous observed time, reboot/gap markers and a separate manually started comparison. The observer works on every page. Approximate SOC remains explicitly approximate for Orange/Silver. No amps, capacity, SOH score or measured-empty claim is invented.

Race arming requires all four fresh valid >=90%; the user then unplugs the four USB cables and confirms Start on Tab5 within120seconds. Confirmation requires fresh valid data but allows the expected voltage/SOC relaxation after removing USB. First two minutes settle; later recent discharge slopes can give a rough linear time to10%, labeled tentative and suppressed across gaps/reboots, rising SOC and too little change. A conservative observation endpoint is voltage <=3.30V continuously for60seconds, labeled LOW / RECHARGE. It is not chemical empty or a power cutoff. Link loss never finishes a participant; observed time and last contact remain visible. Blue is Tab5's only gateway; its disappearance must explicitly warn that every other reading is unavailable.

Persistent compact snapshots use only a new Preferences namespace in existing NVS, every five minutes and on explicit race state changes (comparison and continuous background are separate checked keys), with checked writes/readback. No partition/filesystem formatting or bootloader/NVS erasure. On restart, previous curves remain; an active race becomes interrupted, because time off and battery swaps cannot be measured. Background history resumes with a gap. USB CSV export saves source-age-aware points and summaries. It logs boards, not immutable battery identities: after swapping batteries begin a new comparison and record the pack externally.

UI: Faces / Race tabs, SOC/voltage graph toggle, colored miniature faces plus per-board values, elapsed and observed durations, recent rate and tentative remaining time. Waiting state shows live background curves and charge readiness. Explicit Start confirmation, Stop confirmation, and a synthetic Demo that never feeds/persists the real observer. Demo runs while live sampling continues. Leaving Demo restores actual readings. Low-voltage indication asks for recharge; no command changes loads, charging or power.

Artwork is independent: all active board outlines and screens use manufacturer outer dimensions at one px/mm scale, common unit ruler and source manifest. Silver is second largest after Tab5. Drawings remain simplified illustrations with actual or explicitly historical screen captures.

Verification: deterministic host tests for rates, duplicate/stale filtering, clock wrap, downsampled curves, low endpoint, gateway loss, source resets and restart interruption; device app-only Tab5 install after identity/backup checks; real telemetry, page navigation, nonpersisting demo and saved/reloaded snapshot check; finish not running, no reporter reset/test. Final detail: comparison and always-on background curves are separate. Stopping/interruption freezes the comparison but never suspends LOG.
