# Copy-Face Implementation Plan

> Execute inline; use executing-plans and a final independent code review.

**Goal:** A tested, explicitly synthetic Copy-Face prototype and source-backed
camera feasibility record without accessing hardware before release.

**Architecture:** Pure bounded observation tracker and time-based smoothing,
native CrowPanel eye renderer plus mouth, separate target adapter and preview.

**Tech Stack:** C++14 host tests, ESP-IDF 5.4.2 / LVGL 8.4 P4 build, Python preview.

**Spec:** `projects/copy-face/docs/DESIGN.md` and delegated owner brief.

## Global constraints

Separate app and checkout. No serial access until private handoff. No camera
recording/upload, recognition or emotion inference. Mouth model unverified.
No hardware success claims from builds or synthetic tests. Preserve recovery.

## Review focus

- Confidence/order changes among multiple faces must not cause switching.
- Invalid, stale or reordered detections must not prolong a stale expression.
- Loop stalls and timestamp wrap must retain bounded, smooth behavior.
- Header toggling must preserve layout bounds and an accessible restore action.
- Synthetic images and mouth values must never masquerade as real inference.

## Tasks

1. Write tests for `Tracker::observe(Frame, now)` and `Tracker::step(now, mirror)`;
   see them fail, then implement `core/Tracking.h`. Frame holds eight bounded
   detections and capture time; Pose holds gaze, mouth and tracking state.
2. Reuse native eye source with provenance; add `core/Scene.h` mouth composition
   and deterministic scripted observations. Host-test bounds and render the same
   scene in preview and P4 adapter. Compile a synthetic-only target outside Git.
3. Record V1.0 primary camera/model evidence, prototype controls, tested versus
   pending results, revision log and separate project catalog entry. Refresh main
   before publication and preserve concurrent CrowPanel work. Review all changes.
4. Check private hardware handoff. Only after explicit release verify the actual
   camera and qualify capture/detection, then evaluate a mouth model. If pending,
   keep the hardware untouched and record the exact next step.
